Wire-format compliance is asserted against the canonical JSON examples
maintained alongside the spec at:

- **Repository**: `modelcontextprotocol/modelcontextprotocol`
- **Subpath**: `schema/2026-07-28/examples`
- **Commit SHA** (pin used by `git checkout`): `271ecc9accafdd9b83a3c869fa67c22953b2af80`
- **Captured**: 2026-07-29 (moved to the released `schema/2026-07-28/` path with the 742750af… schema re-pin; see ADR-027 revision log). Prior: 2026-07-28 (c56f0ad2…), 2026-07-02 (6e4cba2d…), 2026-06-10 (1bf94a60…)

`refresh --write` maintains **only the Commit SHA line** here. Any other value
recorded in this file is hand-maintained and will silently rot across a bump —
a subpath tree digest used to be recorded and did exactly that, so it was
dropped rather than re-introduced.

The compliance harness (`src/compliance/`) fetches the pinned tree via
shallow sparse `git clone`, caches under `target/upstream-fixtures/` for
tests and `$TMPDIR/mcp-compliance-2026-07-28/` for the binary, then
asserts that every modeled `compliance::coverage::Case` round-trips
exactly against every `*.json` fixture in its directory.

## Single source of truth

The pinned SHA lives **once** as a `const PIN: Pin` in
`src/compliance/fetch.rs`. This file is human-readable documentation
regenerated by the refresh tool — never edit the SHA here by hand;
update `fetch.rs` and re-run `cargo run --bin mcp-compliance-2026-07-28 -- refresh --write`.

## Refresh workflow

```
cargo run --bin mcp-compliance-2026-07-28 --features compliance -- refresh        # dry-run, diff only
cargo run --bin mcp-compliance-2026-07-28 --features compliance -- refresh --write # bumps pin + this file
```

Refresh fails non-zero if any modeled case regresses under the new pin —
the maintainer must reconcile the diff in the same slice as the bump.
